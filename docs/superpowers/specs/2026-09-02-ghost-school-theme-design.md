# 유령 학교의 저주 — 할로윈 테마 리디자인

## 배경 / 목표

Claude Design으로 만든 시안(`방탈출 리디자인 시안.dc.html`, 4화면: 조 편성 / 교실 선택 / 미션 선택 / 저주 해제)을 실제 `index.html`에 적용한다. 시안에 없는 나머지 학생 화면(QR 스캔, 학년 확인, 문제 풀이, 각종 피드백/모달)도 같은 톤(양피지·나무·돌·유령학교)으로 새로 디자인해서 통일감을 맞춘다. 관리자 화면(`#adminRoot`)은 이번 범위에서 제외 — 지금 스타일 그대로 둔다.

Firebase 데이터 구조, 정답 판정 로직, QR/수동입력, 조 편성·학년 보정 로직 등 기존 동작은 전혀 바꾸지 않는다. 이번 작업은 `#studentRoot`의 시각 표현(HTML 구조 + CSS + 정적 문구/아이콘)만 다시 만드는 것이다.

## 1. 디자인 시스템 (공통 토큰)

- **폰트**: 제목/숫자류 `Nanum Myeongjo`(700~800), 라벨/본문류 `Nanum Gothic`. 구글 폰트 `<link>`를 `#studentRoot`용으로 추가. 기존 `Noto Sans KR`은 `#adminRoot` 전용으로 유지.
- **배경**: 어두운 남보라 `#120d21` 바탕 + 화면별 배경 이미지(`background_castle_gate.png`, `background_mission_select.png`, `background_problem_frame.png` 등) `background-size:cover` + 어둡게 하는 그라디언트 오버레이(가독성 확보용, 시안과 동일 패턴).
- **재질 3종**
  - 양피지 카드: `linear-gradient(170deg, rgba(236,220,180,.96), rgba(214,193,146,.96))`, 글자는 짙은 갈색(`#3f2c14`/`#402d16`/`#5f4a26`). 조 목록, 문제 풀이 프레임, 결과 요약, 각종 안내 모달에 사용.
  - 보라 돌벽 카드: `linear-gradient(170deg, rgba(58,40,96,.9), rgba(34,23,62,.92))` + 금테(`rgba(255,205,130,.4)`). 교실 카드, 잠김 상태에 사용.
  - 초록 성공 카드: `linear-gradient(170deg, rgba(60,86,58,.9), rgba(28,48,32,.92))` + 연두 테두리(`rgba(140,230,160,.5)`). 완료 상태에 사용.
- **포인트 색**: 금색 `#ffcf7a`/`#ffe9b8`(강조 텍스트·버튼), 보라 `#c9b9e8`/`#e2c6ff`(보조 텍스트), 성공 연두 `#9ce6b4`, 오답/경고는 `status_failure.png` 톤에 맞춘 빨강 계열 유지(기존 `--red` 톤을 이 팔레트에 맞게 살짝 채도만 조정).
- **모션**: `drift`(유령·박쥐 부유), `flicker`(랜턴·촛불 깜빡임), `twinkle`(다음 미션 강조). `@media (prefers-reduced-motion: reduce)`에서는 모두 끔.
- **장식 이미지 사용 원칙**: 화면마다 1~3개만 최소로 배치(박쥐/유령/거미줄/반짝임 중심). 화면을 가리거나 텍스트 가독성을 해치지 않는 선에서.

## 2. 이미 디자인된 4화면 → 실데이터 연결

시안의 마크업/스타일을 가져와 각 렌더 함수에 이식한다. 절대 픽셀좌표 대신 `%`/`clamp()` 기반으로 바꿔 태블릿 화면 크기 편차에 대응한다(4절 참고).

- **`renderTeamPick`**: 나무 간판 타이틀("방탈출 놀이" / "유령 학교의 저주" / "조 편성") + 조 목록 양피지 카드. 조원 이름은 지금처럼 한 줄 전체 표시. 조가 편성되지 않은 상태 안내문도 같은 톤의 카드로.
- **`renderHome`**: 좌측 안내 패널(양피지 타이틀 + 저주받은 지도 문구 + 열쇠 진행도 + QR 스캔 버튼) + 우측 3×2 교실 카드 그리드 + 강당 협동미션 카드. 열쇠 진행바, "QR을 못 찾겠어요" 링크, "선생님이 열어주셨어요" 버튼, 도움 요청중 표시는 기존 로직 그대로 카드 안에 얹는다. 상단 finale 배너("협동 미션에 도전할 수 있어요" 등)도 같은 양피지 톤으로.
- **`renderRoomDetail`**: 좌측 조 아이콘 + 열쇠 + 진행요약 + 이전 버튼, 우측 양피지 프레임 안에 8개 미션 아이콘(해결=✅ 오버레이, 다음=twinkle 강조 + sparkles, 잠김=흑백 처리 + padlock 오버레이). 팝업창으로 열렸을 때("✕ 창 닫기")와 같은 창 이동("← 홈으로") 두 경우 모두 지원.
- **`showCelebration`**: 우측 두루마리 결과 카드. 통계는 **푼 문제 / 연 교실 / 단체줄넘기** 3가지만 표시(걸린 시간 항목은 추가 트래킹이 필요해 제외 — 3개 통계를 가로 한 줄로 배치). 좌측 문구·유령·반짝임 장식은 시안 그대로.

## 3. 새로 디자인하는 화면 (시안에 없던 부분)

같은 재질/폰트 시스템 위에서 구성한다.

- **QR 스캔(`openScan`)**: `background_mission_guide.png`(양피지+유령+랜턴) 배경. 카메라 박스는 금테 액자처럼 감싸고, 안내 문구는 양피지 라벨. 수동 코드 입력은 양피지 카드 안 입력창 + 나무 버튼. 도움 요청 버튼도 같은 버튼 스타일.
- **학년 확인(`showGradeGate`)**: 좁은 양피지 카드에 경고 문구, 또래 도움 안내는 보라 계열 박스(기존 파란 계열 대신).
- **문제 풀이(`showQuestionScreen`)**: `background_problem_frame.png` 큰 양피지 프레임 안에 배지(문제ID/학년/교실·단원), 이미지/SVG, 문제 텍스트, 정답 입력+제출(금테 버튼). "풀이 공간"은 어두운 석판(슬레이트) 캔버스 + 흰 분필색 선(기존 남색 선 대신). 잠김/복습 모드도 같은 프레임에 상태 문구만 다르게 표시.
- **정답/오답/잠김 피드백**: `status_success.png` / `status_failure.png` / `status_locked.png` 아이콘 + 위 재질 카드 재사용. 오답 쿨다운 텍스트는 보라 톤 작은 텍스트.
- **선생님 알림 모달("다시 풀어주세요")**: `common_scroll.png`을 헤더 아이콘으로 쓰는 양피지 모달.
- **처음 안내 팝업 / 방 개수 변경 알림**: 현재 `alert()`라 스타일을 못 입히므로, 이 두 곳만 같은 양피지 모달(확인 버튼 포함)로 교체. 문구·내용은 그대로. 그 외 `confirm()`(다른 조 선택, 도움 요청 확인, 관리자 관련)은 브라우저 기본을 유지한다.

## 4. 레이아웃 / 반응형

태블릿 가로가 주 사용 기기이므로, 시안과 같은 비율(약 1180:820)의 "무대(stage)" 컨테이너를 화면 중앙에 두고 내부 좌표는 `%`/`clamp()`로 잡아 다양한 태블릿 크기에 자연스럽게 맞춘다.

세로/좁은 화면(폰)에서도 최대한 지원한다: 무대 컨테이너의 좌우 2분할(좌측 안내 패널 / 우측 콘텐츠) 구조를 `flex-wrap` 또는 세로 스택으로 전환하는 자체 반응형 브레이크포인트(예: `max-width: 700px`)를 두어, 폰에서는 안내 패널이 위로 올라가고 그 아래 콘텐츠가 세로로 쌓이는 형태로 재배치한다. 완전히 별도 디자인을 새로 그리는 것은 아니고, 같은 컴포넌트를 세로로 재배열하는 수준이다. 뷰포트 메타(`user-scalable=no` 등)는 기존 그대로 유지.

## 5. 에셋 반입

`escape_room_assets_transparent_png`의 원본 파일명 그대로 저장소에 `assets/`로 복사해서 참조한다(시안의 `bg_gate` 같은 별칭 대신 `background_castle_gate.png` 등 원본 파일명 사용). 필요한 파일만 선별해서 복사한다 — 배경 6종, 버튼 3종, 교실 아이콘 6종, 공용 아이콘(박쥐/유령/거미줄/열쇠/반짝임/성공·실패·잠김 상태/조 아이콘 5종/미션 아이콘 8종/장식 소품 일부).

## 6. 테스트 / 검증

자동 테스트 대상 로직 변경은 없음(정답 판정, 학년 보정 등 기존 로직 불변이라 `scripts/roster-utils.test.js` 등 기존 테스트는 그대로 통과해야 함). 시각적 변경이므로 로컬에서 `index.html`을 브라우저로 열어 다음을 직접 확인한다: 조 편성 → 교실 선택 → 미션 선택 → QR 스캔(수동입력) → 문제 풀이(정답/오답) → 방 완료 → 강당 협동미션 → 저주 해제 축하 화면까지 전체 플로우, 그리고 태블릿 가로 폭과 좁은 폭(폰) 두 가지 뷰포트에서 레이아웃이 깨지지 않는지.
